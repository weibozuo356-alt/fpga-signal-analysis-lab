## T3-00 任务边界与任务地图

任务三把任务二经DAC产生的模拟正弦信号通过SMA线送回AD/DA板的ADC，FPGA根据ADC采样值检测每个正弦周期的上升穿越，在固定两秒测量门内计数，最后把频率以Hz为单位显示在八位数码管上。

```text
任务二DDS与14位DAC
    ↓ 模拟正弦信号
SMA回环线
    ↓
10位ADC，50 MHz采样
    ↓
1 ms等待 + 10 ms自动幅度校准
    ↓
高、低双门限迟滞穿越检测
    ↓ 每周期一个adc_rising_pulse
2 s测量门计数
    ↓
measured_frequency（Hz，二进制）
    ↓ 更新翻转信号跨时钟域
Double Dabble二进制转BCD
    ↓
八位数码管动态扫描显示
```

本任务复用了任务一的八位数码管扫描、任务二的Clock Wizard、DDS、DAC和频率选择开关。新增部分是50 MHz ADC接口、自动门限、迟滞穿越、定时计数、测量结果跨时钟域以及二进制转BCD。任务四和任务五会继续复用ADC采样、模拟回环和数码管显示，但把“统计周期”换成频谱与失真度计算。

## T3-01 50 MHz ADC时钟和10位采样值

**核心结论：** 50 MHz时钟用于让ADC每20 ns产生一次10位幅度码；它不是正弦信号的周期，也不是为了把模拟信号“恢复”成原来的14位数据。

Clock Wizard把100 MHz板载时钟变成10 MHz与50 MHz：

```verilog
clk_wiz_10m u_clk_wiz_10m (
    .clk_out1 (clk_10m),
    .clk_out2 (clk_50m),
    .reset    (1'b0),
    .locked   (clk_10m_locked),
    .clk_in1  (clk_in)
);
```

其中10 MHz继续驱动DDS/DAC，50 MHz通过ODDR转发给外部ADC，并在FPGA内部采入并行数据：

```verilog
always @(posedge clk_50m) begin
    if (!clk_10m_locked)
        adc_sample <= 10'd0;
    else
        adc_sample <= ad_in;
end
```

ADC采样周期为：

$$
T_{ADC}=\frac{1}{50\ \text{MHz}}=20\ \text{ns}
$$

`ad_in[9:0]`与`adc_sample[9:0]`的范围为0～1023。这个数由外部ADC对引脚上的模拟电压进行量化后产生；例如`adc_sample=650`是ADC当时的原始输出，不是FPGA通过门限公式计算出来的。

任务二的DAC是14位，任务三的ADC是10位，但SMA线上传输的是模拟电压，不是14位数字码。DAC先把14位码变成电压，ADC再把电压重新量化成10位码，因此理想满量程匹配时约16个DAC码对应一个ADC码，DAC低4位所代表的细微幅度差异通常不能在10位ADC码中保留。

**工作过程：** `14位DAC码 → 模拟电压 → 10位ADC重新量化 → adc_sample`。

**易错点：** 20 ns是ADC采样时钟周期；一个1 MHz正弦周期是1 μs，两者不是同一个量。

## T3-02 自动校准怎样得到门限

**核心结论：** 门限不是写死为650，也不是由某一个ADC采样值决定，而是先在10 ms内统计波形最小值与最大值，再计算中点和迟滞宽度。

每次上电或切换频率后执行：

```text
等待模拟输出稳定1 ms
→ 连续采样10 ms并记录min、max
→ 计算范围R=max-min
→ 若R≥32，则计算门限并开始测频
→ 若R<32，则认为信号过小或未接入，重新校准
```

定义：

$$
R=ADC_{max}-ADC_{min}
$$

$$
M=\left\lfloor\frac{ADC_{max}+ADC_{min}}{2}\right\rfloor
$$

$$
H=\max\left(\left\lfloor\frac{R}{8}\right\rfloor,4\right)
$$

$$
ADC_{high}=M+H,\qquad ADC_{low}=M-H
$$

代码对应：

```verilog
wire [9:0] adc_hysteresis_raw = adc_range_next >> 3;
wire [9:0] adc_hysteresis_next =
    (adc_hysteresis_raw < 10'd4) ? 10'd4
                                 : adc_hysteresis_raw;
```

这里的`4`表示4个ADC码，不是4 bit，也不是4 V。`R>=32`是校准成功的最低幅度条件，因为 $32/8=4$，正好达到最小迟滞量。32和4属于本工程选用的抗噪参数，不是所有测频电路都必须使用的理论常数。

例如10 ms内得到`ADC_min=220`、`ADC_max=820`：

$$
R=600,\quad M=520,\quad H=75
$$

因此：

$$
ADC_{low}=445,\qquad ADC_{high}=595
$$

之后某次看到`adc_sample=650`，只表示当前样本已经超过高门限595；650本身没有参与重新计算门限。

## T3-03 为什么使用高、低两个门限

单门限检测容易在噪声附近反复翻转。本工程使用类似施密特触发器的状态逻辑：

```verilog
wire adc_rising_crossing_now =
    calibration_done &&
    !adc_signal_high &&
    (adc_sample >= adc_threshold_high);
```

```text
当前处于低状态，样本≥高门限
→ 产生一个上升穿越脉冲
→ 进入高状态

保持高状态时，即使样本在高门限附近抖动也不再触发

样本≤低门限
→ 回到低状态
→ 允许下一周期再次触发
```

`adc_rising_pulse`只保持一个50 MHz时钟周期，所以脉冲宽度约20 ns。这个20 ns只是“发生一次上升穿越”的事件标志宽度，并不是正弦周期。

理论上，相邻两个有效上升穿越之间相隔一个正弦周期；本工程没有逐周期计算这个时间间隔，而是在固定时间内直接统计穿越次数。

## T3-04 两秒直接计数法

50 MHz时钟计满100,000,000个周期就是2秒：

```verilog
localparam integer FREQUENCY_GATE_CYCLES = 100_000_000;
```

设两秒内统计到的有效穿越数为 $N$，输入频率为 $f$，则：

$$
f=\frac{N}{2\ \text{s}}
$$

代码在测量门结束时执行：

```verilog
measured_frequency <=
    (waveform_cycle_count +
     (adc_rising_crossing_now ? 32'd1 : 32'd0) +
     32'd1) >> 1;
```

- 条件加1：包含测量门最后一个50 MHz周期中可能出现的穿越；
- 固定加1：在整数除以2前完成四舍五入；
- `>>1`：除以2，结果单位为Hz。

例如50 kHz信号在2秒内应产生100,000次穿越，因此显示50,000 Hz。1 MHz信号在2秒内应产生2,000,000次穿越，因此显示1,000,000 Hz。

两秒门时间对应的理论计数分辨率为：

$$
\Delta f=\frac{1}{2\ \text{s}}=0.5\ \text{Hz}
$$

数码管最终显示整数Hz，因此0.5 Hz结果会经过整数取整。分辨率不等于绝对精度；晶振误差、门边界、DDS实际频率、噪声和模拟链路都会影响实测值。

## T3-05 非阻塞赋值和最后一个计数为什么要单独处理

同一个`always @(posedge clk_50m)`中，条件判断使用时钟沿到来前的旧值，所有`<=`的新值在本次时钟沿处理结束后统一生效。

因此测量门最后一个周期如果恰好发生穿越，仅写：

```verilog
measured_frequency <= waveform_cycle_count >> 1;
```

会遗漏当前时钟沿检测到但尚未写入`waveform_cycle_count`的新事件。本工程在表达式中直接加上`adc_rising_crossing_now`，把最后一次穿越包含进去。

## T3-06 测量结果怎样跨到100 MHz显示域

ADC与测频运行在50 MHz，BCD转换和数码管扫描运行在100 MHz `clk_in`。`measured_frequency`在每次两秒测量完成后更新，并在下一次结果到来前保持稳定；`measurement_update_toggle`每得到一个新结果翻转一次。

任务三独立版本使用：

```verilog
measured_frequency_meta <= measured_frequency;
measured_frequency_sync <= measured_frequency_meta;

measurement_update_meta <= measurement_update_toggle;
measurement_update_sync <= measurement_update_meta;
measurement_update_last <= measurement_update_sync;
```

当`measurement_update_sync != measurement_update_last`时，100 MHz域知道有一个完整新结果，可以开始BCD转换。

最终任务四、五集成版本中这组信号改名为`frequency_display_value_meta/sync`与`frequency_display_update_meta/sync/last`，作用相同。此前按旧名字搜索不到代码，是版本整合后的命名差异，并不表示同步逻辑消失。

**实现评估：** 当前多位数据在源域长时间保持稳定，上板已经验证正常。若进一步做严格CDC设计，可在翻转通知前先保持数据若干源时钟，或采用握手/FIFO；这属于可选增强，不是已确认的上板错误。

## T3-07 二进制为什么要转BCD

`measured_frequency=50000`在寄存器里是普通32位二进制，不等于八个十进制显示位。Double Dabble使用64位移位寄存器：

```text
bcd_shift[63:32]：8个BCD数字工作区
bcd_shift[31:0] ：待转换的32位二进制数
```

初始化：

```verilog
bcd_shift <= {32'd0, measured_frequency_sync};
```

每轮先检查左侧八个4位组。某个BCD组大于或等于5时，只给这个4位组加3，然后将整个64位寄存器左移一位。重复32轮后，左32位就是八位BCD结果，右32位已全部移出并补0。

以十进制13，即二进制`1101`为缩短示例：

```text
初始：0000 0000 | 1101
第1轮：无需加3，左移 → 0000 0001 | 1010
第2轮：无需加3，左移 → 0000 0011 | 0100
第3轮：无需加3，左移 → 0000 0110 | 1000
第4轮：个位6≥5，先加3得到9，再左移
        → 0001 0011 | 0000
```

左侧`0001 0011`按两个BCD组解释就是十进制13。加3加在每一个满足条件的BCD四位组上，不是加到整个32位二进制数上。

## T3-13 可直接复述的总结

> 任务三把任务二DAC产生的模拟正弦信号通过SMA线送入10位ADC。Clock Wizard提供50 MHz ADC采样时钟，所以每20 ns得到一个0到1023的幅度码。切换频率后，系统先等待1 ms，再用10 ms统计ADC最大值和最小值，根据中点及幅度范围的八分之一自动生成高、低两个门限。波形从低状态超过高门限时产生一个上升穿越事件，只有回落到低门限后才允许下一次触发，因此每个正弦周期只计一次。系统在2秒门时间内统计穿越次数并除以2，得到以Hz为单位的频率。测量结果通过翻转通知同步到100 MHz显示域，经过Double Dabble转换成八位BCD，再由数码管动态扫描显示。
